# Evaluating Agentic Bioinformatics through Functionality, Evidence, and Validation

This repository contains the search, screening, human-verification, analysis, and visualization pipeline used to construct the evidence map for the manuscript **“Evaluating Agentic Bioinformatics through Functionality, Evidence, and Validation.”**

The pipeline searches **PubMed**, **Europe PMC**, and **arXiv**, harmonizes the retrieved records, removes duplicate and ineligible records, supports manual verification, and generates domain-level reports and statistical visualizations.

## Repository structure

```text
.
├── config/
├── crawl_data/
├── data/
│   └── HumanVerification/
├── data_raw/
│   ├── arxiv/
│   ├── europe_pmc/
│   └── pubmed/
├── filter/
├── logs/
├── outputs/
├── visualizing/
├── run_all_searches.py
├── run_filter.py
└── README.md
```

### `config/`

Contains the configuration files used by the literature-search pipeline.

These files define:

- agent-related search terms;
- domain-specific search terms;
- source-specific query settings;
- publication-date limits;
- output locations;
- filtering and deduplication options.

The domain configuration covers:

- genomics;
- transcriptomics;
- epigenomics;
- proteomics;
- drug discovery;
- computational pathology and bioimaging;
- cross-domain bioinformatics.

The search logic follows the general structure:

```text
agent terms AND domain terms
```

Search terms are divided into source-compatible batches and translated into the field and date syntax required by each database.

### `crawl_data/`

Contains the source-specific code used to retrieve records from:

- PubMed;
- Europe PMC;
- arXiv.

The crawlers preserve retrieval provenance, including the source database, matched agent terms, matched biological domains, and available publication identifiers.

### `data_raw/`

Contains the unfiltered outputs generated by:

```bash
python run_all_searches.py
```

The results are organized by source:

```text
data_raw/arxiv/
data_raw/europe_pmc/
data_raw/pubmed/
```

These files represent the records returned directly by the search stage before cross-source normalization, deduplication, eligibility filtering, or human verification.

The raw files should be retained unchanged so that the search process remains auditable and can be rerun or compared against later retrievals.

### `filter/`

Contains the code used to process records after retrieval.

The filtering pipeline performs the following operations:

1. loads source-specific records from `data_raw/`;
2. converts records to a common schema;
3. checks the configured agent and domain criteria;
4. removes records excluded during automated screening;
5. deduplicates records using publication identifiers and normalized titles;
6. assigns candidate records to biological domains;
7. exports files for manual eligibility assessment.

The main filtering logic is implemented in:

```text
filter/run_pipeline.py
```

The root-level command:

```bash
python run_filter.py
```

runs the filtering pipeline and writes the processed results to `data/`.

### `data/`

Contains the processed outputs generated after running:

```bash
python run_filter.py
```

or, when the pipeline is executed directly:

```bash
python filter/run_pipeline.py
```

The files in this directory represent successive stages of normalization, automated screening, deduplication, domain assignment, and candidate preparation. Intermediate files should be preserved because they document how raw search results were transformed into the final human-verification set.

The most important review-ready files are stored in `data/HumanVerification/`.

### `data/HumanVerification/`

Contains the records and decisions used during manual eligibility assessment.

#### `04_candidates_sorted_by_domain.csv`

The primary candidate file produced after automated filtering and deduplication.

Records are organized by biological domain to support full-text review and consistent eligibility assessment. Each row represents a candidate publication retained for human verification.

#### `Manually Identified.csv`

Contains additional publications identified outside the main database-derived candidate set, such as records found through targeted searches, citation tracing, system-name searches, companion papers, or updated versions.

These records must undergo the same eligibility assessment and coding rules as database-derived candidates.

#### `AgenticSystem.csv`

Contains the consolidated set of publications classified as agentic or agent-adjacent systems.

This file supports the system evidence map and includes the records used for domain-level Functionality-Evidence-Validation analysis.

#### `Benchmark.csv`

Contains publications classified as benchmarks, evaluation suites, or directly relevant workflow-evaluation resources.

These records are analyzed separately from agentic-system records, although a publication may contribute to both analytic categories when it reports both a system and a benchmark resource.

#### Human-verification decision file(s)

The human-verification file records the manual decision for each candidate in `04_candidates_sorted_by_domain.csv`.

The decision fields should document:

- whether the candidate was included or excluded;
- the eligibility category;
- the reason for exclusion when excluded;
- whether the record represents an agentic system, an agent-adjacent system, a benchmark/evaluation resource, or more than one analytic category;
- the assigned primary biological domain;
- notes supporting the decision;
- publication or system identifiers needed for later coding and auditing.

These files provide the audit trail linking automated screening to the final evidence map.

### `logs/`

Contains logs produced during literature retrieval and pipeline execution.

Logs may include:

- query execution times;
- source-specific retrieval counts;
- query-batch information;
- API or connection errors;
- retries;
- excluded or malformed records;
- deduplication summaries;
- pipeline warnings.

Retaining these logs is important for troubleshooting and for documenting when and how each source was searched.

### `outputs/`

Contains generated reports and summaries for each biological category.

Outputs may include:

- record counts by domain;
- full-agentic and agent-adjacent summaries;
- benchmark-resource summaries;
- Functionality, Evidence, and Validation distributions;
- publication-year summaries;
- intermediate tables used in the manuscript or supplementary material.

Files in this directory should be treated as generated results rather than manually edited source data.

### `visualizing/`

Contains scripts used to generate statistical figures and visual summaries from the finalized coding tables.

These scripts may be used to visualize:

- Functionality breadth;
- Evidence breadth;
- Validation-level composition;
- Validation qualifiers;
- full-agentic versus agent-adjacent sensitivity analyses;
- domain-level comparisons;
- publication-year composition.

Figures should be regenerated from the finalized, adjudicated data rather than edited manually.

## Environment setup

A Conda environment is recommended to keep the search and analysis dependencies reproducible.

If the repository includes an `environment.yml` file, create the environment with:

```bash
conda env create -f environment.yml
```

Activate the environment using the environment name specified in `environment.yml`:

```bash
conda activate <environment-name>
```

If the environment already exists, update it with:

```bash
conda env update -f environment.yml --prune
```

If no `environment.yml` is currently available, export the working environment before release:

```bash
conda env export --no-builds > environment.yml
```

## Running the pipeline

### 1. Configure search terms

Review the files in `config/` before running the searches.

Confirm:

- the publication-date range;
- agent-related search terms;
- domain-specific terms;
- source-specific settings;
- output paths.

For the evidence map described in the manuscript, the publication window is:

```text
1 January 2022 through 1 September 2026
```

### 2. Retrieve records

Run all configured searches:

```bash
python run_all_searches.py
```

Expected output locations:

```text
data_raw/arxiv/
data_raw/europe_pmc/
data_raw/pubmed/
```

Review `logs/` after completion to identify failed queries, incomplete batches, API errors, or retry events.

### 3. Filter and deduplicate records

Run:

```bash
python run_filter.py
```

This command processes the raw search results and writes normalized, filtered, deduplicated, and domain-assigned records to `data/`.

The underlying pipeline may also be run directly with:

```bash
python filter/run_pipeline.py
```

Do not run both commands as separate analysis stages unless `run_filter.py` is configured for a different purpose. In the standard workflow, `run_filter.py` acts as the root-level entry point for the filtering pipeline.

### 4. Perform human verification

Review:

```text
data/HumanVerification/04_candidates_sorted_by_domain.csv
data/HumanVerification/Manually Identified.csv
```

For every candidate:

1. inspect the title and abstract;
2. consult the full text, supplementary material, repository, or benchmark documentation when required;
3. apply the eligibility criteria consistently;
4. record the inclusion or exclusion decision;
5. document the reason for exclusion;
6. assign the appropriate system, benchmark, and domain categories;
7. retain notes and supporting evidence for auditing.

After verification, the retained records are consolidated into:

```text
data/HumanVerification/AgenticSystem.csv
data/HumanVerification/Benchmark.csv
```

### 5. Generate reports and figures

Use the analysis and visualization scripts to generate category-level reports in `outputs/` and figures from the finalized coding data.

Before generating final manuscript figures, confirm that:

- human-verification decisions are complete;
- duplicate publications have been consolidated;
- preprint and archival versions are handled consistently;
- agentic-system and benchmark assignments are finalized;
- adjudicated FEV assignments are used;
- no manually edited summary has replaced a reproducible pipeline output.

## Reproducibility and audit trail

To preserve the auditability of the evidence map:

- do not modify files in `data_raw/` after retrieval;
- retain source and query provenance for every record;
- preserve intermediate filtering and deduplication outputs;
- document all manual inclusion and exclusion decisions;
- retain the original independent coding before adjudication;
- store adjudication rationales separately from the original assignments;
- generate summaries and figures from the finalized coding files;
- record the software environment used for each release;
- archive the repository version associated with the submitted manuscript.
